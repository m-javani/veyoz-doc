Architecture at a glance

A distributed in-memory engine, built on proven foundations.

Overview

One engine. Three jobs.

Veyoz does three things: filters inventory to a small candidate set, computes the correct price for each candidate, and returns the cheapest valid result. Everything else — storage, replication, routing — exists to make those three jobs fast and reliable.

Query Path

Filter. Price. Rank.

01

Filter

Compressed bitmaps reduce a hundred thousand properties to a few hundred candidates in microseconds — by geography, dates, rating, facilities, and policies.

02

Price

Each candidate is priced for the query — rates, child supplements, charges, promotions — in parallel, with no per-candidate lock and no shared state.

03

Rank

The priced set is sorted and returned. Cheapest first. Deterministic across every node.

Built On

Proven foundations. No experiments.

Rust

The entire engine — storage, consensus, query execution, networking — is written in Rust. Predictable memory, no garbage collection pauses, no runtime surprises.

Raft consensus

Built on TiKV's production-grade Raft implementation. The same consensus layer that powers TiDB. Mature, well-tested, actively maintained.

QUIC transport

Node-to-node communication over QUIC. Multiplexed streams, built-in encryption, no head-of-line blocking.

H3 geospatial

Uber's hierarchical hexagonal grid for geographic indexing. Numeric cell identifiers, uniform coverage, no tree traversal on the query path.

Tokio async runtime

The industry-standard async runtime for Rust. Battle-tested at scale across the ecosystem.

Rayon parallel execution

Work-stealing parallelism for the price computation stage. Every search uses the full available core set, with backpressure that keeps tail latency bounded.

Consistency

Replicated. Deterministic. Pause-free.

Leader writes, followers read

Each shard is a Raft cluster. The leader orders and replicates writes. Followers hold the full dataset and serve reads. Read capacity scales by adding followers.

Deterministic state

Every replica applies the same commands in the same order and produces byte-identical state. There is no "almost consistent" mode.

Pause-free snapshots

Snapshots are taken without stopping the cluster. Query execution is never blocked. Restarts and node additions stream from the latest snapshot without replaying the full history.

No external dependencies

No ZooKeeper. No etcd. No Consul. No external service registry. The cluster is self-contained.

Operations

Nothing surprising at 3 AM.

Rolling restarts

Nodes restart one at a time. Followers continue serving reads while a node is out. No maintenance window required.

Fast bootstrap

A new node loads from a compressed snapshot in seconds and joins the cluster. Adding read capacity is a deployment, not a project.

Small binary

One executable. No JVM, no interpreter, no sidecar. Runs on VMs, containers, or bare metal.

Predictable memory

In-memory state with a fixed footprint per shard. No surprise allocations, no heap growth, no GC.

Scope

Deliberate limits.

Veyoz does one thing. These are the boundaries.

  • · Hot window only. Long-range and archived dates stay in your own storage.
  • · No ranking. Cheapest valid result wins. Ranking is your business.
  • · No aggregator ingestion. You send normalized IDs and models.
  • · Fixed schema. Attributes are codes and numbers, not free-form data.
